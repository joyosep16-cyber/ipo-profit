=============================================
   공모주 수익 관리 앱 - 배포 및 실행 안내
=============================================


[ CMD 창 문제 해결 - 백그라운드 실행 방법 ]
─────────────────────────────────────────

기존 "공모주앱 실행.bat" 은 실행 중 검은 CMD 창이 계속 떠 있어야 합니다.
창을 닫으면 앱도 같이 종료됩니다.

아래 두 파일로 대신 사용하면 CMD 창 없이 실행됩니다.

  ▶ 실행 : "공모주앱 실행(백그라운드).vbs" 더블클릭
            → CMD 창 없이 앱이 백그라운드에서 조용히 실행됩니다
            → 브라우저가 자동으로 열립니다

  ■ 종료 : "앱 종료.bat" 더블클릭
            → 백그라운드에서 실행 중인 앱을 완전히 종료합니다

  ★ 앱 실행 중 확인 방법 : 브라우저에서 http://localhost:8501 접속해보기


─────────────────────────────────────────
[ Streamlit Cloud 배포 - PC 없이 24시간 접속 ]
─────────────────────────────────────────

Streamlit Cloud 를 이용하면 내 PC가 꺼져 있어도
인터넷만 되면 어디서든 접속할 수 있습니다.


[사전 준비]
  · GitHub 계정 (github.com 에서 무료 가입)
  · Supabase 계정 (supabase.com 에서 무료 가입) - 데이터 저장용
  · Git 설치 (git-scm.com 에서 무료 다운로드)


─────────────────────────────────────────
1단계 : GitHub 저장소 만들기
─────────────────────────────────────────

1. github.com 접속 후 로그인
2. 오른쪽 위 "+" 버튼 클릭 → "New repository" 클릭
3. Repository name 에 이름 입력 (예: ipo-profit)
4. "Private" 선택 (비공개)
5. "Create repository" 클릭


─────────────────────────────────────────
2단계 : 코드를 GitHub에 올리기
─────────────────────────────────────────

Git 설치 후, CMD 창을 열고 아래 명령어를 순서대로 입력하세요.

  cd "c:\Users\ADMIN\OneDrive\바탕 화면\IPO Subscription Profit"
  git init
  git add .
  git commit -m "first commit"
  git remote add origin https://github.com/[내아이디]/ipo-profit.git
  git push -u origin main

※ [내아이디] 부분을 본인 GitHub 아이디로 바꾸세요
※ 처음 push 시 GitHub 로그인 창이 뜰 수 있습니다 (로그인 하면 됩니다)


─────────────────────────────────────────
3단계 : Supabase 데이터베이스 만들기
─────────────────────────────────────────

1. supabase.com 접속 → "Start your project" 클릭
2. GitHub 계정으로 로그인
3. "New project" 클릭
4. 프로젝트 이름 입력, 비밀번호 설정 (★ 비밀번호 꼭 메모해두기!)
5. 지역 선택 → "Create new project" 클릭 (1~2분 대기)
6. 완료되면 왼쪽 메뉴에서 "Settings" → "Database" 클릭
7. 아래로 스크롤 → "Connection string" 항목 → "URI" 탭 클릭
8. 아래와 같은 주소가 보임 → 복사해두기

   postgresql://postgres:joyosep2612*@db.fpifxqxmlfhvzkimlagc.supabase.co:5432/postgres
   (비밀번호 부분이 [YOUR-PASSWORD] 로 표시되면 직접 입력한 비밀번호로 교체)


─────────────────────────────────────────
4단계 : Streamlit Cloud 배포
─────────────────────────────────────────

1. share.streamlit.io 접속 → GitHub 계정으로 로그인
2. "New app" 버튼 클릭
3. Repository : 아까 만든 저장소 선택 (예: 내아이디/ipo-profit)
4. Branch : main
5. Main file path : app.py
6. 오른쪽 아래 "Advanced settings" 클릭
7. "Secrets" 탭에 아래 내용 입력 (각 값을 본인 것으로 교체)

   DISCORD_WEBHOOK_URL = "https://discord.com/api/webhooks/..."
   HIGH_RETURN_THRESHOLD = "200"
   DATABASE_URL = "postgresql://postgres:비밀번호@db.xxxx.supabase.co:5432/postgres"

   ※ NGROK_AUTH_TOKEN 은 입력하지 않아도 됩니다
      (Streamlit Cloud 는 이미 공개 URL 이 있어서 ngrok 이 필요 없음)

8. "Deploy!" 버튼 클릭
9. 2~3분 기다리면 완료!


─────────────────────────────────────────
5단계 : 배포 완료 후
─────────────────────────────────────────

배포가 완료되면 아래 형태의 주소가 생깁니다.

  https://내아이디-ipo-profit-xxxx.streamlit.app

이 주소를 북마크에 저장하거나 가족에게 공유하면
PC가 꺼져 있어도 언제든지 접속할 수 있습니다!

모바일에서도 이 주소로 바로 접속 가능합니다.


─────────────────────────────────────────
6단계 : 코드 수정 후 반영하는 방법
─────────────────────────────────────────

앱을 수정한 뒤 GitHub에 다시 올리면 자동으로 배포됩니다.

  git add .
  git commit -m "수정 내용"
  git push

GitHub에 올라가면 Streamlit Cloud 가 자동으로 앱을 다시 시작합니다.


─────────────────────────────────────────
[ 로컬 실행 vs Streamlit Cloud 비교 ]
─────────────────────────────────────────

  구분            로컬 실행              Streamlit Cloud
  ──────────────────────────────────────────────────────
  PC 켜야 함?     예 (켜져 있어야 함)    아니오 (24시간)
  설치 필요?      Python 설치 필요       없음 (브라우저만)
  접속 주소       매번 바뀜 (ngrok)      항상 고정 URL
  데이터 위치     내 PC                  Supabase 클라우드
  비용            무료                   무료 (제한 있음)


─────────────────────────────────────────
[ 문제가 생겼을 때 ]
─────────────────────────────────────────

Q. git push 시 오류가 나요
A. git config --global user.email "내이메일"
   git config --global user.name "내이름"
   위 두 줄을 먼저 실행한 뒤 다시 push 해보세요

Q. Streamlit Cloud 배포 중 오류가 나요
A. 배포 화면에서 "Manage app" → 로그 확인
   requirements.txt 의 패키지 문제일 가능성이 높습니다

Q. Supabase 연결이 안 돼요
A. DATABASE_URL 의 비밀번호 부분을 다시 확인하세요
   특수문자가 있으면 URL 인코딩이 필요할 수 있습니다
   (예: @ → %40, # → %23)
